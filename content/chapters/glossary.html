Agent harness
All the software around an AI model that turns it into a working agent: it sends messages, runs tools, remembers things, checks permissions and shows results.
Agent loop
The repeating cycle at the heart of an agent: send the conversation to the model, run any tools it asks for, add the results, and go again until it is done.
AI agent
An AI model that can also take actions (search, edit files, send messages) and decide its next step, not just reply with text.
Allowlist
A list of things that are explicitly permitted. Anything not on the list is refused.
API gateway
One front door for all requests to a set of services, handling sign-in checks, routing and limits.
Approval gate / human in the loop
A stop where a person must say yes before the agent does something risky.
At-least-once delivery
A message system promise that every message arrives, but some may arrive more than once. Receivers must handle repeats.
Atomic
Done as one indivisible step: it either fully happens or does not happen at all.
Audit log
A permanent, tamper-resistant record of important actions, kept for security checks and legal needs.
Audit trail
A tamper-resistant record of who did what and when, kept for security reviews and compliance checks.
Backoff
Waiting a little longer after each failed attempt before trying again, often with a random extra delay (jitter).
Broker
A service that receives messages from senders and passes them to receivers, such as a message queue server.
Cached prefix
The opening part of a request that the provider has saved. Requests that begin with the same text reuse it, which is faster and cheaper.
Chargeback
Charging each team or customer for the AI usage they caused, using tracked token costs.
Checkpoint
A saved copy of the agent's state at a moment in time, so a run can resume or roll back to it.
CI (continuous integration)
An automatic system that builds and tests code every time someone changes it.
Compaction
Shrinking an old conversation (for example by summarising it) so it still fits in the context window.
Compensating action
An action that undoes an earlier step's effect, used when a multi-step job fails partway.
Compliance (SOC 2, ISO 27001, GDPR, HIPAA, EU AI Act)
Laws and standards a business must meet for security, privacy and responsible AI. They shape what must be logged, kept and protected.
Container
A packaged, isolated environment for running a program with its own files and limits.
Content block
One piece of a message: text, an image, a tool call or a tool result. A message can hold several.
Context window
The amount of text the model can see at one time. Anything outside it is invisible to the model.
Correlation ID
One ID attached to every message and log line that belong to the same request, so they can be linked later.
Data residency
Rules that require data to stay in a certain country or region, for example EU data stored only in the EU.
Dispatcher
The part of the harness that receives a tool call, finds the right tool and runs it.
DLP / redaction
Data loss prevention: finding sensitive data and hiding or removing it before it is stored or shown.
Durable execution (Temporal, Step Functions)
Running a long multi-step job so that it can survive crashes and restarts and continue exactly where it stopped.
Embedding
A list of numbers that captures the meaning of a piece of text, so similar texts get similar numbers.
ETag / compare-and-set
A version tag on a stored item. A write only succeeds if the tag still matches, so two writers cannot silently overwrite each other.
Eval
A repeatable test of an AI agent: a fixed task with checks on what the agent did and said.
Event loop
A single worker that waits for many things at once (network replies, timers) and handles each one as it becomes ready.
Event streaming (Kafka, Pub/Sub)
A shared pipe where services publish events (something happened) and others subscribe to react to them.
Fail closed
When a check cannot decide (for example it times out), the answer is 'no'. The safe default.
Feature flag
A switch that turns a feature on or off for some customers without releasing new code.
Fencing token
A number that goes up each time a lock is granted. Storage rejects writes carrying an old number, so a worker whose lock expired cannot overwrite newer work.
Future
A placeholder for a result that is not ready yet. You can wait for it or attach a callback.
Guardrail
An automatic check on what goes into or comes out of the agent, such as blocking personal data or unsafe actions.
Hash / content hash
A short fingerprint made from data. Any change to the data changes the fingerprint.
Hook
A point where your own code can plug in and run, for example before every tool call.
Idempotency key
A unique ID sent with an action so the receiver can spot a repeat and skip it, instead of doing the action twice.
Idempotent
Safe to run twice: doing it again gives the same result and no extra side effects, like pressing a lift button twice.
Interface
A promise in code about what a component can do (its methods), without saying how it does it.
Kill switch
A feature flag used to stop something quickly in an emergency, even for sessions that are already running.
Lease
A lock that expires on its own after a set time unless it is renewed, so a crashed holder cannot block others forever.
Least privilege
Giving each user, agent or tool only the access it truly needs, and nothing more.
Legal hold
An order to keep certain data and not delete it, usually because of a lawsuit or investigation.
LLM gateway
One central service all model calls go through, handling login keys, routing between providers, limits, cost tracking and logs.
Lock
A way to make sure only one worker changes something at a time.
MCP
Model Context Protocol. A standard way to plug tools and data sources into an AI agent. An MCP server lists its tools; the harness calls them.
Model / LLM
Large language model. The AI that reads text and writes text. It runs on a provider's servers and is called over the internet.
Multi-tenant
One platform serving many customer organisations at once, with walls between their data.
Object storage
Cheap, durable storage for large files (blobs), such as transcripts, documents and images.
Observability / OpenTelemetry
Being able to see what the system is doing through traces, metrics and logs. OpenTelemetry is the common open standard for collecting them.
Orchestrator
The main agent or service that hands out work to other agents and combines their results.
Outbox
A table where actions are written down first, in the same transaction as the data change, and sent out afterwards. Nothing is lost if a crash happens in between.
PII
Personally identifiable information: names, emails, phone numbers and other data that points to a real person.
Policy engine (OPA, Cedar)
A separate service that answers 'is this allowed?' using written rules, so permission logic is not scattered through the code.
Principal
The identity an action is performed as: a person, a service or an agent acting for someone.
Prompt
Everything sent to the model in one request: instructions, the conversation so far, and tool descriptions.
Prompt cache
Saved work the model provider can reuse when a new request starts with exactly the same text as an earlier one. Any change near the start breaks the reuse.
Prompt injection
Hidden instructions inside a web page, file or email that try to trick the agent into doing something the user did not ask for.
Pseudocode
Simplified example code that shows the idea, not code you can copy and run as is.
Pure function
A function whose output depends only on its inputs and that changes nothing else. Easy to test and safe to reuse.
Queue
A waiting line for work items. Producers add items; workers take them off one by one.
Rate limit
A cap on how many requests or tokens you may send in a period. Going over it returns an error (HTTP 429) asking you to wait.
RBAC / ABAC
Role-based and attribute-based access control: permissions given by job role, or by facts like department, region or data type.
Regression gate
A test step that blocks a release if quality drops below the previous version.
Replica
A copy of a database or service kept in sync with the original, for speed or for backup.
Retry-After
A hint in an error reply that says how long to wait before trying again.
Row-level security
Database rules that only show each user or tenant the rows they are allowed to see.
Sandbox
A sealed-off place where code or tools run, so a mistake cannot harm the rest of the system.
Schema / JSON Schema
A description of what shape some data must have: which fields, what types, which are required. JSON Schema is the common format for tool inputs.
SDK
Software development kit: a library that makes it easy for developers to call a service from their code.
Secrets manager (Vault, KMS)
A secure store for passwords, keys and tokens, so they never sit in code, prompts or logs.
Side effect
A change in the outside world caused by an action, such as an email sent or money moved. Side effects are why retries need care.
SIEM
Security information and event management: a central system where security teams collect and search logs to spot attacks.
SLO
Service level objective: a reliability target, such as 99.9 percent of requests answered within 5 seconds.
Span
One timed step inside a trace, such as one model call or one tool call.
SSE (server-sent events)
A simple way for a server to keep a connection open and push updates to a browser, often used to stream model replies.
SSO / OIDC
Single sign-on: people log in once with their company account. OIDC is a common standard for doing this.
stop_reason
The field in a model's reply that says why it stopped, for example because it finished or because it wants to call a tool.
Streaming
Sending the model's reply in small pieces as it is written, so the user sees words appear right away.
Stub
A simple stand-in for a real component, used to connect to it remotely or to fake it in tests.
Subagent
A helper agent started by a main agent to do one part of a job, often in parallel, with its own separate context.
System prompt
Standing instructions sent at the start of every request, such as the agent's role and rules.
Tenant
One customer organisation sharing a platform with others. Tenants' data must be kept strictly apart.
Token
A small piece of text, roughly three quarters of a word. Models count, limit and charge by tokens.
Tool
An action the agent can ask for, such as reading a file, searching the web or querying a database.
Tool call / tool_use
The model's request to run a tool. It names the tool and gives the inputs. The harness runs it, not the model.
Tool result / tool_result
The answer sent back to the model after a tool runs. If the tool failed, it is marked with the is_error flag.
Trace
A record that follows one request through every step and service it touched, with timings, linked by one ID.
Transaction
A group of changes that either all happen or none happen.
Transcript
The full record of a conversation: every message, tool call and tool result, in order.
Trust boundary
A line in the system where data from a less trusted source (a user, a web page, the model) must be checked before it is believed.
TTL (time to live)
How long something is kept before it expires automatically.
Vector store
A database that stores text as lists of numbers (embeddings) so it can find passages with a similar meaning.
Webhook
A web address one system calls automatically to tell another system that something happened.
Workload identity
A way for a running service to prove who it is to cloud systems without storing a long-lived password.
